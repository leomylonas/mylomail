# Current handoff

## Current state

Everything below is implemented, tested and described in `docs/architecture.md` (§13 epics and the sections named). This file lists only what is live: results of the last verification pass, open decisions, and risks.

- Outlook-style renderer and compose (command bar, ruled From/To/Cc/Bcc/Subject rows, cross-account From menu, Outlook quote header with the signature above it), message window with the full action set, background-activity dialog, 12/24-hour setting, folder pinning/hiding/multi-select and server-projected unread counts, Gmail account-wide backfill with an adaptive request budget.
- Message HTML is prepared and served by the backend (`MessageHtmlPreparer`, `/messages/{id}/frame` under its own CSP); the renderer holds no sanitiser.
- Mutation recovery asks the provider about one message (`IMailProvider.FindMessageAsync`) and can re-resolve a current provider occurrence for a permanent delete when local membership is temporarily absent; a failed settle never stalls unrelated changes; failing batches back off.

## Verification (pass of 2026-10-20)

- **Unit and integration:** `pnpm check` green (format, tsc, eslint, stylelint, website, build, 1033 .NET tests, 430 Vitest). CI on `5c94ba5` green.
- **E2E:** the whole Playwright suite ran: 30 of 32 passed, 1 skipped (`NativeAttachmentOpen`, packaged build only) and 1 failed — the compose-switch spec, on leftover server-side drafts (the matrix IMAP server keeps its Drafts across runs). That spec now uses a unique draft subject and passes on repeated runs.
- **Fault injection:** `Category=FaultInjection` — 73 scenarios pass. Scenarios added this period were each shown to fail with the behaviour removed (reconciliation without a folder walk; an occurrence-free delete not settled as done; a failed settle not blocking other changes; draft pushes serialised; drain backoff).
- **Conformance:** IMAP on QRESYNC, CONDSTORE and BASIC — pass, including `FindMessage_follows_a_message_through_a_move_and_reports_it_gone_after_deletion`. The live IMAP classes shared one account's INBOX/Archive/Trash and failed one at a time when run in parallel; they are now one serial xunit collection and passed three runs in a row. **Gmail and Graph live conformance have not been run, and `check:deep` cannot pass until they can:** the Gmail test account's token cache (`GMAIL_TOKEN_CACHE_BASE64`) predates the full-access scope, so the conformance delete opens Google's consent screen; that used to hang the run for ever (this is why `check:deep` printed nothing for 29 minutes) and now ends after three minutes with a failed delete. Re-mint the token cache with `https://mail.google.com/` granted, then run `pnpm check:live-providers`. Until then the Gmail and Graph `FindMessageAsync` are covered by request-shape tests (`MessageLookupTests`) only.
- **Independent invariant reviews (reviewer role, two slices) and a parity review** found: (1) the online-backup connections bypassed the SQLite pragma interceptor — fixed (`SqlitePragmaInterceptor.ApplyTo`); (2) a permanent delete with no local occurrences was completed without asking the provider, which wrongly completes for a Gmail message that has no labels — fixed (`MutationReconciler.ConfirmGoneAsync`); (3) settlement rewrote the provider-owned unread counts — fixed: it now writes only `Mailbox.UnreadConfirmedDelta`, which each topology snapshot resets (a confirmation landing between a provider read and its commit can still leave the figure one off until the next pass); (4) documentation drift, now corrected.
- **Staged-page and Gmail-pacing change (2026-10-22):** a Gmail poll that finds nothing no longer stages an empty `StagedChangeEvent` (`ChangeStreamService.CarriesChanges`); the budget's post-refusal recovery is capped at a rising ceiling. `StagedPageTests` was shown to fail with the invariant broken: dropping `Removed` from the predicate fails the removal case, and making the predicate always true fails the empty-page cases and the behavioural scenario. An independent reviewer found no violation. 1190 .NET tests pass. Not exercised against a live Gmail account, so the effect on the real quota is unmeasured.
- **Cross-account move (2026-10-22):** `CrossAccountTransfer` + `CrossAccountTransferService`/`TransferJobs`, `IMailProvider.ImportMessageAsync` (IMAP APPEND, Gmail `messages.import`, Microsoft 365 via the mailbox import/export API), hub `MoveMessagesToAccount`, drag onto another account's folder and per-account "Move to" entries. An independent invariant review found: overlapping runs could import twice (fixed: per-account lock + atomic claim), concurrent requests could start two transfers (unique filtered index), a single empty lookup was treated as proof of absence (3-minute window), a same-`Message-ID` message could be mistaken for the copy (`BaselineCopies`), source-provider throttling was attributed to the target (`TransferSourceException`), tombstone GC could reclaim a message mid-move (fixed), endless retries (`MaximumAttempts`) and clock-based removal idempotence (removal id = transfer id); IMAP byte fidelity is pinned by `ImapImportFidelityTests`. Two review points are accepted limits and written up in architecture §6. Each protection was shown to fail when removed (dispatched write: 4 scenarios; look-before-retry: 2; duplicate-removal guard: 1; run lock + claim: 1; unique index: 2; baseline: 1; window: 2; GC retention: 1). The conformance test `Import_stores_a_findable_copy…` passes on all three IMAP tiers; Gmail and Graph conformance are skipped without credentials, so **Gmail `messages.import` is unexercised against the real service**. E2E `MoveBetweenAccounts` drags a message between two real IMAP servers and checks both. The message window's own toolbar does not offer cross-account move yet. **Microsoft 365 as a target** (added afterwards): draft-from-MIME, export, clear the draft flag in the stream, import; the call sequence and the flag rewrite are tested against a scripted Graph (`GraphImportTests`), but **it has never run against the real service**: the beta endpoints, the id forms they accept (the folder id is translated from the immutable form first) and the exact stream layout are unverified, and the Entra app registration must have the delegated `MailboxItem.ImportExport` permission added and consented (work or school accounts only).
- Not run: `pnpm check:deep` as one command (it produced no output for 29 minutes; its steps were run individually as above); the Windows/macOS matrix (`cross-platform-check` runs only on tags or manual dispatch); the pre-migration backup against a copy of the real database.

## Live risks / decisions

- Hub additions (`GetProblems`, `GetContentQueue`, `PrioritiseContent`, `RetryFailedDownloads`, `EmptyMailbox`) enqueue or read only; `EmptyMailbox` goes through the existing `DeletePermanently` mutation per message and refuses any folder whose effective role is not Trash or Junk.
- `ContentPriority` and the credential cache are in-memory by design (hints, not recovery state); the durable queue is `MessageContentState`.
- The legacy migration tests seed through the current model; they add and drop newer `Accounts` columns around the seed (`AddNewerAccountColumnsAsync`) and must be extended when another Account column is added.
- Gmail expired-history and native RSVP coverage remain conditional on external fixtures.
- **Gmail account-wide backfill (written without running anything; unverified).** Gmail coverage is one walk per account (`messages.list` with no label filter, `includeSpamTrash`, one `format=full` get per message). Cursor on the new `AccountCoverageState` (migration `AddAccountCoverageState`, hand-written snapshot entry), mailbox rows mirror it, progress reported once on the Inbox row, one owner per account (`CoverageRegistry.AccountWalkScope`, `SyncJobs.StartCoverage`/`AccountCoveragePageAsync`). Late labels are caught up through the per-mailbox path. Per-mailbox ranges are refused for Gmail. Every Gmail request goes through `GmailRequestBudget` (10,000 units/min, burst 2,500). Messages mapping to no local mailbox are fetched, counted and **not stored** (tombstone GC would collect them): confirm this against "do not drop them". Review: `docs/reviews/gmail-account-backfill.md` (self-review only; an independent `reviewer` pass is still owed). `MutationReconciler.ObserveAsync` still walks every label in full on `ReconcileThenRetry` recovery.

- **Export wizard (2026-10-24):** replaces the old per-account "Export" section in account settings. `ExportJobs` (own `export` queue, one worker), `Export/` (`ExportLayout`, `ExportNames`, `MboxFormat`), hub `StartBulkExport(StartExportRequestDto)`, `GetExports`, `GetExportFolders`; renderer `Components/ExportWizard`. Catch-up passes include mail arriving mid-export; mbox resume truncates to the saved offset (shown to fail without the truncation). PST is shown disabled. Found and fixed on the way: the old `GetLatestAsync` ordered by a `DateTimeOffset`, which SQLite cannot do, so the old status view never worked. Not done: the message-window toolbar and an Electron-level e2e of cancel/restart mid-export; mbox date order within a folder follows `ReceivedAt`.
